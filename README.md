### 📦 知识产权侵权案件 AI Agent 审核提效项目
> 目前阿里巴巴知识产权保护平台已运营多年，侵权案件早已分门别类，部分由规则引擎直接审核，部分能依靠算法审核，还有部分案件难以聚类 or 规则化审核，只能依靠人工审核。构建一个审核 Agent 帮助人审提效甚至代替人审成为了本项目方向

**项目职责**: 项目技术 PM、架构师、后端唯一开发  
**技术栈**: Spring Boot, LangChain, MCP  
**项目模块**: 提示词工程、审核 Agent 构建、评测系统  
**项目亮点**:
- 🔬 本项目拥有实际的落地场景调研，拥有 LLM 审核能力的评估体系
- 🤖 通过手搓 Agent 框架了解 Agent 在审核场景的能力边界，降低了本项目嵌入通用 Agent 框架 LangChain 的使用和调试难度
- 🚀 同时工程化提示词模版，和评测系统，提高项目版本迭代速度和稳定性
- 💡 审核 Agent 上线至今已降低可观的人力审核成本，且审核一致性基本已靠齐人工审核

### 📦 维权系统-规则引擎重构项目
> 系统层面上：Groovy 脚本执行引擎带来的机器性能下降、全局优先级带来信息过载难维护、长期的面条代码导致可测性很低、极容易导致预期之外的问题等，缺少无损档发布，定时发布，灰度发布等高级功能。业务层面上：纯规则引擎无业务语义无法满足精细化运营等

**项目职责**: 项目技术 PM、架构师、后端唯一开发  
**技术栈**: Spring Boot, DDD 四层架构设计, 管理态和运行态重写  
**项目模块**: 领域发现与统一语言、事件风暴机制、历史规则迁移计划和详细的灰度与回滚计划  
**关键挑战与解决**:
- ✅ **如何提前验证新引擎？** 同一条线上流量请求跑双系统，分类统计一致性；同时为了不拖慢线上 RT，异步解耦跑新系统
- 🔄 **如何平滑灰度切换？** 业务层面按用户等级，系统层面按最小完整执行力度（动作）灰度，配置细粒度切换开关，搭建一致性监控大盘实时监测灰度效果
- ⚙️ **如何高效执行？** 对特征层进行分类：常量、实时变量、日变化变量、准实时变量 I 等，不同的数据取数成本不同，小二填写完规则表达式后，系统给出优化方案（短路 & 二叉树旋转）
